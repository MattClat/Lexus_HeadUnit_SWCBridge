Lean mode, explained

Lean mode has one goal: SWC Bridge should almost never be a running app, so it's almost never running when the car switches off. It gets there with three ideas: Android can start the app on demand, every job sets an exit timer, and the app ends itself when the timer runs out.

01

Three ideas it's built on

An app vs. its process

The app is the installed code. The process is that code actually loaded in memory and running. A process can be created and destroyed many times a drive while the app stays installed.

Force-stop is a flag on the app. The head unit only sets it on apps whose process is alive at switch-off.

Doorbells in the manifest

The manifest lists the announcements SWC Bridge wants to hear. Android keeps that list even when no process exists. When one arrives, Android creates the process and hands it the message.

Lean mode is the default

It's on whenever the “Keep bridge running” switch is off, and that switch defaults to off. Every lean-mode branch in the code asks this one question.

02

The life of one process

STATE 0
Not running Nothing in memory. This is where it should be at switch-off.
DOORBELL
Android creates the process Wheel press, boot signal, or you tapping the icon. SwcApp.onCreate · SwcApp.java 26–41
WORK
Does its one job Sends NEXT to Poweramp, runs the startup ramp, or shows the screen.
ARM TIMER
Lean.holdFor(ms) “Keep me alive at least this long, then check if I can quit.” Lean.java 61–69
TIMER FIRES
EXIT: anything still needed? No → the process ends itself and goes back to state 0. Lean.java 71–92
This loop repeats all drive. If another doorbell rings while the timer is counting, the timer is just pushed later. The process is reused, not recreated.

06 · WHAT LEAN MODE SWITCHES OFF
Anything that would keep it alive, or bring it back
Permanent notification (foreground service)Tells Android “never kill me”. BridgeService 130–133.
15-minute watchdog alarmWould restart it while parked. WatchdogReceiver.cancel 47–52.
Own MediaSession (“Input 2”)Only works in a process that stays up. BridgeService 189.
Automatic restart (START_STICKY)Returns START_NOT_STICKY instead, so Android never revives it behind our back. BridgeService 120.
